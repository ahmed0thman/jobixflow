# Gap Analysis — New Requirements vs. Live Product

**Phase 2 deliverable.** Built from every file in `.claude/audit/` (Phase 1: 47 files, 88 screenshots, 4 web roles + shared login mapped live via browser) cross-referenced against `.claude/docs/NEW-REQUIREMENTS.md`, `.claude/docs/BRDs/*.md`, `.claude/docs/open-questions.md`, and `.claude/rules/01-business-invariants.md`.

## How to read this

Each table row cites the **requirement** (with its rule/question ID), the **live page(s)** it touches (linked into `audit/`), a **change type**, what concretely needs to be **built**, and any **open question** that blocks or narrows the design. Rows carry enough restated context to scope a Figma page without re-opening the BRD.

**Change type legend**
- **New page** — no live equivalent exists at all; greenfield design
- **New flow** — a multi-step process (may touch several new + existing pages)
- **Modify** — a live page exists and needs changes/additions
- **New component** — a piece of UI (modal, widget, panel) added to an existing page
- **Dev-fix only** — a live bug with no design action required; listed here because it changes what "current behavior" means, not because a screen needs to be drawn

Per `Rule 00 · R00-5`, nothing here asserts a screen "is missing" absolutely — only that it was **not found live** during this audit pass. Per `Rule 00 · R00-4`, rows are written to the depth the sources support; thin areas (Reports, Service Call Fee) stay thin rather than being padded.

## Priority findings — read this before the table

Six things from Phase 1 materially change how the financial/communications work should be scoped, in order of urgency:

1. **A per-job "Technician Ledger" already exists as a linked route and crashes with a reproducible 500 error** on every job tested (`company-admin/jobs/jobs.md`). This is the single clearest evidence that backend financial-ledger work has already started. **Coordinate with the developer before designing the Technician Account screens — there may be a partial data model and view to build on, not a blank slate.** Flag the bug itself to the developer immediately, independent of any design timeline.
2. **The two-layer Live Map (`LOC-003`) is fully built and functional today** (`company-dispatcher/live-map/live-map.md`) — real Google Maps JS integration, working layer toggles, technician→job deep link. This directly contradicts `CLAUDE.md`'s "Missing entirely" list. **Review this as a reference implementation before designing this screen from scratch.**
3. **Partial Twilio infrastructure already exists**: real Call SIDs, a `technician_to_client` call-type enum, and a `twilio_identity` field already assigned per technician (`company-admin/call-logs/call-logs.md`, `company-admin/audit-log/audit-log.md`). The masking/proxy-number/webhook-routing behavior is the genuinely new part — not "the entire masked-communication layer," as `NEW-REQUIREMENTS.md §2` currently states. **Get the developer to clarify exactly what's already wired before scoping §2's design work** — this could change estimation materially.
4. **The `service_types` table is seeded entirely with person names**, confirmed at the source on the dedicated Service Types admin page (`platform-dispatcher/service-types/service-types.md`), not just a downstream chart bug. This is a functional blocker for job intake today, not a design concern — but it means **the "Service Type" field cannot be used as a real, meaningful filter/report dimension until fixed**, which directly affects the Reports overhaul (`§4`) and any Service-Type condition filter.
5. **A live "Priority" field (Low/Medium/High) conflicts with the resolved `Q-05`** (binary Now/Scheduled) (`platform-dispatcher/new-job/new-job.md`). These may be two different fields colliding on one name. **Do not silently reconcile — this needs a client/developer decision before any redesign touches job priority anywhere.**
6. **A 3-way technician-count discrepancy for the same company** — 11 (Technicians page) / 51 (Company Dispatcher's Technicians page) / 101 (Users KPI tile) (`company-admin/technicians/technicians.md`, `company-admin/users/users.md`, `company-dispatcher/technicians/technicians.md`). Until resolved, **no technician-count figure from any live screen should be trusted as a design reference.**
